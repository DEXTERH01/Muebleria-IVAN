# Protocolo breve de prueba de usuario

## Objetivo

Encontrar bloqueos en los flujos de catálogo y cotización antes de presentar la demo. Realizar la sesión en la URL de demo y usar datos controlados; no registrar información personal real.

## Preparación

- Invitar de cinco a ocho participantes que no hayan desarrollado la aplicación.
- Explicar que se evalúa el sistema, no a la persona, y pedir autorización antes de tomar notas.
- Abrir una sesión privada del navegador con los datos iniciales de demo disponibles.
- Registrar solo el código anónimo `P01`, `P02`, etc.; no nombres ni contactos.
- Cronometrar cada tarea y anotar si se completó sin ayuda, con ayuda o no se completó.

## Tareas

1. Encontrar un mueble en el catálogo y abrir su detalle.
2. Configurar medidas, material y acabado para obtener una estimación.
3. Enviar una solicitud de cotización con un contacto de prueba.
4. Iniciar sesión con una cuenta de demostración y encontrar la cotización.
5. Como operador o administrador de demo, revisar la cotización, convertirla a pedido y localizarla en el taller.
6. Encontrar la recomendación de producción y explicar si cambiaría automáticamente el pedido.

No pedir a participantes que realicen pagos, carguen vouchers reales o usen datos personales.

## Registro por tarea

| P01 | 1–6 | | | |

Duplicar la fila por participante y tarea. Después de cada sesión preguntar: “¿Qué fue lo más confuso?” y “¿Qué esperabas que ocurriera?”.

## Encuesta SUS

Tras completar las tareas, responder cada frase de 1 (muy en desacuerdo) a 5 (muy de acuerdo):

1. Me gustaría usar este sistema con frecuencia.
2. El sistema me pareció innecesariamente complejo.
3. El sistema me pareció fácil de usar.
4. Creo que necesitaría ayuda técnica para usar el sistema.
5. Las funciones del sistema me parecieron bien integradas.
6. El sistema me pareció inconsistente.
7. Creo que otras personas aprenderían a usarlo rápidamente.
8. El sistema me pareció difícil de usar.
9. Me sentí seguro usando el sistema.
10. Necesité aprender muchas cosas antes de empezar.

Para calcular SUS, en los ítems impares restar 1 a la respuesta; en los pares restar la respuesta a 5. Sumar los diez valores y multiplicar por 2.5. Reportar promedio, cantidad de participantes y limitaciones de la muestra; no presentar el promedio como prueba de calidad comercial.

## Resumen de resultados

Informar tasa de tareas completadas (`tareas completadas / tareas intentadas`), mediana de tiempo por tarea, promedio SUS, errores observados y tres correcciones prioritarias. No rellenar esta sección hasta ejecutar las sesiones.
